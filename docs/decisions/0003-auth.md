# ADR 0003 — Authentication design

**Status:** Accepted

- **Passwords:** Argon2id via `@node-rs/argon2` (prebuilt binaries, so no compiler needed on Windows), OWASP minimum parameters. Policy: 12–128 characters, no composition rules.
- **Sessions:** opaque random token in an HttpOnly, SameSite=Lax cookie (`Secure` in production). The database stores only the token's SHA-256 hash, so a database leak does not yield usable cookies. A new token is issued on every login; logout deletes the row, so replaying a copied cookie fails.
- **CSRF:** two layers. (1) Origin allow-list (`CLIENT_URL`) for all unsafe methods. (2) Authenticated writes require `X-CSRF-Token`, a stateless HMAC of the session token hash under `SESSION_SECRET`.
- **Enumeration:** login failures are identical for unknown email and wrong password, with a dummy Argon2 verification to even out timing. Registration does reveal an existing email (409) — a deliberate usability trade-off, protected by rate limiting; revisit when email verification exists.
- **Same-origin deployment:** the SPA calls `/api` on its own origin (Vite proxy in dev). Hosting the API on a different registrable domain would need cookie `SameSite=None; Secure` and revisiting this ADR.
- **Ownership:** `req.user.id` is derived only from the session; controllers must never read an owner ID from the request.
